# پرامپت آماده Codex برای ادغام ماژول ضبط ۳۶۰ درجه V2

این متن را همراه پوشه `vehicle-360-recorder-v2/` به Codex بدهید. Codex باید به مخزن **فعلی** اپلیکیشن بازدید خودرو دسترسی داشته باشد؛ هیچ کدام از فایل‌های این پکیج به‌تنهایی حاوی سورس کامل آن اپ یا endpointهای واقعی بک‌اند نیستند.

---

در پروژه اپلیکیشن بازدید خودرو، ماژول مستقل `vehicle-360-recorder-v2` را طبق `IMPLEMENTATION_GUIDE_FA.md` در جریان ضبط ویدیوی ۳۶۰ درجه یکپارچه کن. اول سورس و معماری واقعی پروژه را بررسی کن و سپس با کمترین تغییر لازم پیاده‌سازی کن.

**قبل از تغییر فایل‌ها:**

1. `git status`, `git worktree list`, `git branch -vv`, `git log -5 --oneline` را بررسی کن. بر اساس اسم worktree حدس نزن کدام نسخه نهایی است. تغییرات کاری موجود را حفظ کن، چیزی را پاک یا overwrite نکن و از شاخه اختیاری 3D به‌عنوان مبنای پیش‌فرض استفاده نکن.
2. `AGENTS.md`/`AGENT.md` و قراردادهای پروژه، ساختار routing، build، IndexedDB، queue، evidence، submit و قفل پس از submit را مطالعه کن.
3. فایل‌های ماژول و `assets/360-recording/ghost-guides/manifest.json` را باز کن. این پوشه شامل دقیقاً **۸ فایل WebP شفاف** است. تصاویر Ghost را با SVG جایگزین نکن و SVGهای قدیمی خودرو را در صفحه جدید استفاده نکن. SVG آیکن‌های کنترلی مجاز است.
4. API واقعی و توابع صف آپلود موجود را از کد/مستندات استخراج کن؛ endpoint فرضی یا token/privateKey سمت فرانت‌اند تولید نکن.

**قابلیت الزامی:**

- فارسی RTL، طرح موبایل‌فرست، پوسته 100dvh بدون document scroll، رنگ #2563EB، حفظ سازگاری بصری با اپ فعلی.
- فقط ضبط مستقیم با `getUserMedia` و `MediaRecorder`. هیچ مسیر انتخاب/آپلود ویدیوی آماده، file-picker یا gallery fallback ایجاد نکن.
- دقیقاً هشت Ghost Guide تصویری، به ترتیب رابطِ درخواستی:
  1. جلو → ghost-front.webp
  2. جلو ۴۵ راست → ghost-front-45-right.webp
  3. راست → ghost-right.webp
  4. عقب ۴۵ چپ → ghost-rear-45-left.webp
  5. عقب → ghost-rear.webp
  6. عقب ۴۵ راست → ghost-rear-45-right.webp
  7. چپ → ghost-left.webp
  8. جلو ۴۵ چپ → ghost-front-45-left.webp
- تغییر بین نماها دستی است؛ تشخیص خودکار زاویه/پوشش را وانمود نکن. «راست/چپ» از دید خود خودرو تعریف می‌شود؛ صحت بصری نمای فایل‌ها را بررسی کن.
- WebP با transparency و `pointer-events:none` روی live camera نمایش داده شود؛ به تصویر MediaRecorder وارد نشود و دچار crop یا stretch نامناسب نشود. امکان نمایش/مخفی‌سازی راهنما بدون توقف ضبط وجود داشته باشد.
- حلقه فقط «زمان ضبط فعال نسبت به هدف» را نشان بدهد؛ مکث زمان را freeze کند؛ تکمیل ۱۰۰٪ نه پایان اجباری ضبط است نه اثبات پوشش ۳۶۰ درجه.
- شروع/مکث/ادامه/پایان، بازبینی، ضبط مجدد، ذخیره Blob محلی و پیام خطای مرورگر. هیچ مسیر file input نداشته باشد.
- از صف durable آپلود موجود پروژه، نه صف مستقل جدید، استفاده کن. اطمینان حاصل کن handoff idempotent و revision-based، offline/retry/cancellation و stale job replacement درست بماند.
- evidence ویدیوی ۳۶۰ درجه از ۱۲ عکس الزامی و عدد کیلومتر مستقل باشد و با قوانین submit/receipt/lock موجود هماهنگ شود. بعد از submit اجازه تغییر ویدیو نده.
- هنگام page close/unmount همه media tracks و object URLs آزاد شوند.
- MIME/codecهای پشتیبانی‌شده را در گوشی واقعی بررسی کن؛ فرض نکن همه مرورگرها WebM یکسان می‌دهند.
- هیچ داده باینری در MSSQL ذخیره نکن؛ API ASP.NET Core فایل را در فضای خصوصی ساختار `GUI_{CustomerId}/{InspectionId}/...` (منطبق با معماری سرور) ذخیره کند و DB فقط آدرس و metadata داشته باشد.

**مراحل تحویل:**

1. ابتدا یک گزارش کوتاه از فایل‌های واقعی پروژه، route، queue و وضعیت موجود ارائه کن.
2. کامپوننت‌های مستقل را به معماری واقعی پروژه تبدیل/وصل کن و مسیر assetها و کش Service Worker را بررسی کن.
3. bridge واقعی queue را با توابع موجود بساز و سناریوی retake/revision/cancellation را تست کن.
4. unit/integration tests را اجرا کن؛ سناریوهای مجوز دوربین، offline، reload، pause، stop، retake، قفل submit و ارسال دوباره را پوشش بده.
5. صفحه واقعی روی viewportهای موبایل و RTL را تست کن، screenshot واقعی و ماکاپ را مقایسه کن و اختلاف‌ها را رفع کن.
6. در پایان فهرست فایل‌های تغییرکرده، تست‌های اجراشده، commitهای احتمالی و قسمت‌هایی که هنوز نیازمند API یا تست روی دستگاه واقعی‌اند را گزارش کن. هیچ تستِ اجرا‌نشده‌ای را موفق اعلام نکن.

**نکته:** صفحه مستقل V2 به خودی خود به صف آپلود بک‌اند وصل نشده؛ `src/integration/upload-adapter.js` صرفاً interface را فراهم می‌کند. بدون bridge واقعی، ادعای uploaded/verified نکن.
